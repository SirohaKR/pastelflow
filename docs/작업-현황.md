## 구조 메모

- **서버**: `server/index.js`(Express 5, API·업로드), `server/db.js`(페이지·DB 저장소, `node:sqlite`, 공용/개인 권한), `server/users.js`(계정·세션·초대), `server/realtime.js`(Hocuspocus 동시 편집 + 이벤트 웹소켓), `server/widgets.js`(홈 위젯, 사람별)
- **계정**: 비밀번호는 scrypt, 세션 토큰은 sha256 해시로 저장(쿠키 `pf_session`, 30일). 초대는 1인·7일
- **권한**: 페이지 자리는 `pages.private_owner`(개인) 또는 `pages.space_id`(스페이스), 둘 다 NULL 이면 전체 공용. 하위·DB 항목은 부모 값을 따름. 조건은 `server/db.js` 의 `VISIBLE_SQL` 하나로 모음. 모든 페이지 API와 `/collab` 연결, 접속자 알림에서 확인
- **역할**: 권한 단계 1 보기 / 2 편집 / 3 편집·삭제 / 4 관리. 전체 공용은 `users.role`(admin·full·edit·view), 스페이스는 `space_members.role`(owner·full·edit·view), 개인 페이지는 주인이 4. `pages.locked` 가 자기나 위쪽 페이지에 있으면 4 가 아닌 사람은 1(보기). 계산은 `server/db.js` 의 `scopeLevel`·`levelFor`, 화면은 `src/roles.ts`. 페이지 응답에 `access`·`lockedAny` 가 들어감
- **즐겨찾기**: `favorites(user_id, page_id, created_at)` 표에 사람마다 저장. 목록·상세 응답의 `favorite` 는 요청한 사람 기준. `PATCH /api/pages/:id { favorite }` 는 보기 권한이면 되고, `updated_at` 을 바꾸지 않고 `changed` 알림도 보내지 않음. 예전 `pages.favorite` 값은 서버가 켜질 때(또는 첫 관리자 만들 때) 가장 먼저 만든 관리자의 즐겨찾기로 옮기고 0 으로 비움 (컬럼은 남아 있지만 더는 안 씀)
- **구역 사이드바**: 화면 상태 `zone`('shared' / 'private' / 스페이스 id, localStorage `pf-zone`). 도우미는 `src/zones.ts`. 페이지를 열면 그 페이지 구역으로 바뀜. 스페이스 홈 주소는 `/s/:id` (`src/components/SpaceHome.tsx`, 아이콘은 같은 파일의 `SpaceIcon`)
- **카테고리**: `categories(id, space_id, private_owner, name, position)` — 페이지와 같은 자리 규칙(`VISIBLE_SQL`)으로 보임. 만들기·고치기·지우기는 그 자리 권한 4(관리). `pages.category_id` 는 최상위 페이지만 쓰고, 자리가 바뀌거나 하위로 들어가면 서버가 비움. API `/api/categories`
- **스페이스**: `spaces`(+ `image` 아이콘 사진 주소, `/uploads/…` 만 받음), `space_members(role: owner|member)`. 누구나 만들고 만든 사람이 owner. owner 또는 전체 관리자만 설정·멤버 변경. 마지막 owner 는 나갈 수 없음. 지우면 안의 페이지는 지운 사람의 개인 휴지통으로
- **동시 편집**: 본문 진실은 `pages.ydoc`(Yjs 상태). 저장할 때 `@blocknote/server-util` 로 JSON 본문(`content`)도 같이 갱신 → 검색·복사·홈 위젯이 그대로 동작. REST 로 `content` 를 바꾸면 `ydoc` 을 비워서 다음에 JSON 에서 다시 만듦
- **이벤트**: `/events` 웹소켓. 페이지·DB 를 바꾸는 요청이 끝나면 `changed` 알림(요청의 `X-Client-Id` 로 보낸 탭은 무시), 탭마다 보고 있는 페이지를 받아 `presence` 로 알림
- **화면**: `src/App.tsx`(주소: `/` 홈, `/p/:id` 페이지, `/w/:id` 위젯 상세), `src/components/database/*`, `src/components/home/*`
- **위젯 데이터**: 위젯마다 `config` JSON에 저장. 모양은 `src/components/home/model.ts`
- **차트 색**: `--chart` 토큰(강조색별, 라이트·다크 각각 대비 검사 통과값). 파스텔 원색은 다크 모드 막대로 쓰면 너무 흐림
- **로컬 빌드 주의**: OneDrive 폴더 안에서는 Vite가 `dist`를 비우다 비정상 종료함 → `rm -rf dist` 후 빌드

## 미비 사항 · 할 일

### ✅ 사용자 계정과 협업 (0.5.0 에서 완료)

아래는 설계 당시 메모예요. 구글 로그인만 남았어요.

사용자와 정한 방향: **공용 + 개인 페이지**, **초대 링크로만 가입**, 자체 계정 먼저(구글 로그인은 HTTPS 도메인 생긴 뒤).

1. **계정**: `users`(아이디, scrypt 비밀번호, 별명, 프로필 사진, 색, 관리자/멤버), `sessions`(토큰 해시, 만료), `invites`(코드, 만료, 사용 여부)
   - 첫 실행 시 관리자 계정 만들기 화면. `APP_PASSWORD`는 더 이상 쓰지 않음
   - API 초안: `/api/auth/status·setup·login·logout·register`, `/api/me`(프로필·비밀번호), `/api/admin/invites`, `/api/users`
2. **권한**: `pages.private_owner` 컬럼(NULL=공용, 사용자 id=개인). 하위 페이지·DB 항목은 부모 값을 물려받음. 모든 페이지 API에서 접근 확인
   - 위젯(`widgets.user_id`)과 테마 설정(`ui:<사용자id>`)은 사람마다 따로. 기존 데이터는 첫 관리자에게 넘김
3. **실시간 동시 편집**: Yjs v13 + Hocuspocus(`@hocuspocus/server`·`@hocuspocus/provider` 4.7.x)
   - 화면: `withCollaboration()` (`@blocknote/core/yjs`)에 `fragment`, `provider`, `user{name,color}`, `showCursorLabels: 'always'` → 다른 사람 커서와 이름표 표시
   - 서버: 같은 HTTP 서버에 웹소켓 연결(`/collab`). `pages.ydoc` BLOB에 저장. 처음 열 때 기존 JSON 본문을 `@blocknote/server-util`로 Y 문서로 바꾸고, 저장할 때 다시 JSON으로 바꿔 `content`도 갱신(검색·복사·홈 위젯이 계속 동작하도록)
   - 페이지 복사 시 `ydoc`은 비워 두고 JSON에서 다시 만들기
4. **변경 알림**: `/events` 웹소켓으로 "페이지 바뀜", "DB 바뀜", "누가 어느 페이지를 보는지"를 알림. 요청마다 `X-Client-Id`를 붙여서 내가 일으킨 알림은 무시
5. **화면**: 로그인·가입(초대 링크)·프로필(별명·사진·색·비밀번호)·관리자(초대·멤버) 화면, 사이드바 '공용'/'내 페이지' 구역, 위쪽에 지금 보는 사람 프로필 사진

### 협업 기능 미비 사항

- **구글 로그인**: HTTPS 도메인이 생기면 OAuth 클라이언트를 만들어 붙이기 (`GOOGLE_CLIENT_ID` 등 환경 변수로 켜는 방식 예정)
- **권한이 바뀐 순간**: 누가 보고 있는 페이지를 다른 사람이 '내 페이지'로 옮기거나 스페이스에서 그 사람을 빼도, 이미 열려 있는 동시 편집 연결은 새로 고칠 때까지 유지됨 (사이드바·목록에서는 바로 사라짐)
- **즐겨찾기 알림**: 즐겨찾기는 바꿔도 알림을 보내지 않아서, 같은 사람이 다른 탭·기기에 열어 둔 사이드바는 새로 고치거나 다른 변경 알림이 올 때 맞춰짐
- **잠금·역할이 바뀐 순간 이미 열려 있는 동시 편집 연결**은 다시 연결될 때까지 예전 권한(편집/보기)을 유지해요. 화면 버튼은 바로 바뀌어요
- **데이터베이스 보기 전용**은 추가 버튼을 숨기고 수정 시도를 막는 방식이라, 일부 입력 칸은 눌러지지만 저장되지 않고 안내만 떠요
- **카테고리 끌어서 옮기기**: 카테고리 순서는 ⋯ 메뉴의 위로/아래로만. 페이지를 '카테고리 없음'으로 빼는 건 끌어 놓기가 아니라 ⋯ 메뉴로만 됨
- **홈 '최근·즐겨찾기' 위젯**은 구역과 상관없이 내 즐겨찾기를 모두 보여 줌 (사이드바만 구역별)
- **스페이스 순서 바꾸기**: 서버에는 `position` 이 있지만 화면에서 끌어서 바꾸는 기능은 아직 없음
- **전체 관리자의 스페이스 목록**: `/api/admin/spaces` 는 있지만, 멤버가 아닌 스페이스를 관리하는 화면은 아직 없음
- **데이터베이스 표·속성**은 실시간 병합이 아니라 "바뀌면 다시 불러오기" 방식. 두 사람이 같은 칸을 동시에 고치면 나중에 저장한 값이 남음
- **페이지 제목**도 같은 방식이라, 두 사람이 동시에 제목을 고치면 나중 값이 남음
- **프로필 사진**은 업로드 폴더에 남아 있어서 바꿔도 예전 파일이 지워지지 않음
- 시험은 같은 PC의 두 주소(localhost / 127.0.0.1)로 두 계정을 띄워서 함. 실제 다른 기기 두 대로는 아직 안 해 봄

### 그 밖에

- **파일 속성에서 지운 파일**은 업로드 폴더에 그대로 남아요(다른 곳에서 같은 파일을 쓸 수 있어서 바로 지우지 않음). 쓰지 않는 파일 정리 기능은 아직 없어요
- **에디터 스키마**는 `server/shared/editorSchema.js` 하나로 서버(동시 편집 저장 변환)와 화면이 같이 써요. 새 블록·요소를 추가할 때 여기에 넣어야 저장 중에 사라지지 않아요
- **이미 있는 파일 블록을 표 칸으로 옮기는 기능**은 없어요. 표 칸에 다시 끌어 놓거나 `/` 메뉴로 넣어야 해요

- **확인 필요**: 끌어서 옮기기(사이드바·칸반·캘린더·타임라인·위젯·링크 표)를 실제 마우스로 시험하지 못함. 코드로 보낸 이벤트로만 확인
- **도커 빌드**: 개발 PC에서는 도커가 꺼져 있어 직접 빌드해 보지 못함. NAS에서 빌드해서 쓰는 중
- **앱으로 설치(PWA)**: 매니페스트·아이콘 추가 필요. HTTPS 도메인이 있어야 설치 버튼이 뜸
- **내보내기/가져오기**: 전체 데이터 zip 백업·복원 버튼 없음 (지금은 `data` 폴더를 직접 복사)
- **위젯 아이디어**: 날씨, 포모도로 타이머, 기분 기록
- **알려진 한계**
  - 타임라인은 오늘 기준 앞뒤 일정 범위만 그림(주 단위 84일, 월 단위 300일). 범위 밖 항목은 화살표로 이동
  - 위젯 내용(가계부 기록 등)은 위젯 하나의 JSON에 모두 들어가서 아주 많이 쌓이면(200KB 제한) 나눠야 함
